2. Passo a passo para atualizar a página

Use este procedimento sempre que alterar resultados/analise_monitoramento.html e quiser refletir a mudança no site. Ele usa uma pasta temporária (git worktree), então o seu main e as pastas locais não são tocados.

  1. Revise o arquivo local antes de publicar Abra resultados/analise_monitoramento.html no navegador e passe pelo checklist de cuidados. Tudo o que for publicado fica público.
  2. Abra o terminal na pasta do projeto e confira o login do gh 
    cd ~/Documentos/Projetos/MeusProjetos/Permanentes/pn-0001
gh auth status
    Se aparecer "not logged in", veja Refazer o login.
  3. Crie uma pasta temporária com o branch gh-pages 
    git fetch origin
git worktree add /tmp/pn-ghp gh-pages
git -C /tmp/pn-ghp pull --ff-only
  4. Copie a versão nova por cima do index.html 
    cp resultados/analise_monitoramento.html /tmp/pn-ghp/index.html
git -C /tmp/pn-ghp status --short   # deve mostrar só:  M index.html
    Se aparecer qualquer outro arquivo além de index.html, pare e investigue antes de continuar.
  5. Faça o commit e envie 
    git -C /tmp/pn-ghp add index.html
git -C /tmp/pn-ghp commit -m "Atualiza análise de monitoramento (descreva a mudança)"
git -C /tmp/pn-ghp push
  6. Remova a pasta temporária 
    git worktree remove /tmp/pn-ghp
  7. Confirme que o site foi reconstruído (leva de 30 s a 2 min) 
    gh api repos/pedromfnakashima/pn-0001/pages/builds/latest --jq '.status, .updated_at'
# "built" = pronto · "building" = aguarde · "errored" = veja Problemas comuns
    Depois abra o link e recarregue sem cache (Ctrl+Shift+R; no celular, feche e reabra a aba).
Versão em um único bloco (para quem já conhece o processo)
cd ~/Documentos/Projetos/MeusProjetos/Permanentes/pn-0001 \
&& git fetch origin \
&& git worktree add /tmp/pn-ghp gh-pages \
&& git -C /tmp/pn-ghp pull --ff-only \
&& cp resultados/analise_monitoramento.html /tmp/pn-ghp/index.html \
&& git -C /tmp/pn-ghp add index.html \
&& git -C /tmp/pn-ghp commit -m "Atualiza análise de monitoramento" \
&& git -C /tmp/pn-ghp push \
; git worktree remove /tmp/pn-ghp

Se o commit falhar com "nothing to commit", o arquivo publicado já é idêntico ao local e não há nada para atualizar.

Voltar para uma versão anterior da página

Cada atualização é um commit no gh-pages, então dá para desfazer a última:

git fetch origin
git log --oneline origin/gh-pages          # lista as versões publicadas
git worktree add /tmp/pn-ghp gh-pages
git -C /tmp/pn-ghp pull --ff-only
git -C /tmp/pn-ghp revert --no-edit HEAD   # desfaz a última publicação
git -C /tmp/pn-ghp push
git worktree remove /tmp/pn-ghp

3. Publicar outras páginas no mesmo site

Cada arquivo .html no branch gh-pages vira um endereço próprio. Para publicar, por exemplo, este guia ou uma nova análise sem substituir a principal:

cd ~/Documentos/Projetos/MeusProjetos/Permanentes/pn-0001
git fetch origin
git worktree add /tmp/pn-ghp gh-pages
git -C /tmp/pn-ghp pull --ff-only
cp resultados/NOME_DO_ARQUIVO.html /tmp/pn-ghp/NOME_DO_ARQUIVO.html
git -C /tmp/pn-ghp add NOME_DO_ARQUIVO.html
git -C /tmp/pn-ghp commit -m "Publica NOME_DO_ARQUIVO"
git -C /tmp/pn-ghp push
git worktree remove /tmp/pn-ghp

O endereço será https://pedromfnakashima.github.io/pn-0001/NOME_DO_ARQUIVO.html. Use nomes sem espaços nem acentos (ex.: analise_credores_2026.html).

AtençãoNão use index.html como destino, a menos que queira substituir a página principal. Não copie pastas inteiras para o gh-pages: copie só os arquivos HTML revisados.

4. Compartilhar com terceiros

  1. Envie o link https://pedromfnakashima.github.io/pn-0001/ funciona em qualquer navegador, no computador ou no celular, e não exige conta no GitHub. A página tem modo claro/escuro, gráficos interativos (passe o mouse ou toque) e tabelas que se expandem.
  2. Contextualize na mensagem Sugestão de texto: 
    Segue a análise das despesas do Governo de MS (jan/2015 a ago/2025),
com base em dados do Portal da Transparência:
https://pedromfnakashima.github.io/pn-0001/

Valores nominais (sem correção pela inflação). A projeção de 2025 é
estimada a partir de jan–ago. A seção "Qualidade dos dados" lista as
limitações e os erros encontrados nos arquivos de origem.
  3. Avise quando atualizar O link continua o mesmo após cada atualização. Informe a data da nova versão (o cabeçalho da página mostra "gerado em …"; atualize essa data no HTML antes de publicar).
  4. Se a pessoa precisar do arquivo Ela pode salvar a página pelo navegador (Ctrl+S, "Página completa") ou imprimir em PDF (Ctrl+P). O HTML é autocontido e funciona offline.
Alternativa privadaSe no futuro precisar compartilhar algo só com pessoas específicas, não use o GitHub Pages, que é sempre público nesta conta. Use um link privado (Artifact do claude.ai, Google Drive com acesso restrito ou envio do arquivo por e-mail).

5. Cuidados antes de cada publicação

Público e permanenteTudo o que vai para o GitHub Pages fica acessível a qualquer pessoa e pode ser indexado por buscadores ou arquivado (ex.: archive.org). Mesmo depois de apagada, uma versão antiga continua no histórico do branch gh-pages, que é público.
  • A página não contém nomes de servidores nem dados da planilha Consolidado - Desvio da media.xlsx (dados pessoais por nome).
  • Pessoas físicas aparecem anonimizadas (como "Pessoa física A/B" na seção "Casos estranhos").
  • Menções a empresas em "Casos estranhos" mantêm a ressalva de que são sinais para investigação e não acusações.
  • Nenhum arquivo de salvos/ (PDF, XLSX, PPTX) foi copiado para o gh-pages.
  • git -C /tmp/pn-ghp status --short mostra apenas os arquivos HTML que você pretendia publicar.
  • A data "gerado em …" no cabeçalho foi atualizada.
  • Números novos foram conferidos com as planilhas de origem.
Nunca façagit add . ou git add -A no main deste projeto: isso incluiria salvos/ (≈107 MB com dados pessoais) num repositório público. Se quiser versionar o projeto, adicione antes salvos/ e anotacoes/ ao .gitignore.

7. Problemas comuns

"You are not logged into any GitHub hosts" / refazer o login do gh

Rode o login em um terminal normal (fora do Claude Code), para ver o código de uso único na tela:

gh auth login -h github.com -p https -w
gh auth setup-git

O terminal mostra um código no formato XXXX-XXXX e copia esse código para a área de transferência. Abra github.com/login/device, cole o código e autorize. O código não aparece no app do GitHub no celular, só no terminal. Se rodar dentro do Claude Code com !, o comando vai para segundo plano e o código fica escondido; peça ao Claude para ler a saída.

"gh: comando não encontrado"

O gh foi instalado em ~/.local/bin/gh, sem sudo. Confira se essa pasta está no PATH:

ls -l ~/.local/bin/gh
echo $PATH | tr ':' '\n' | grep .local/bin

Para atualizar o gh, baixe o gh_X.Y.Z_linux_amd64.tar.gz mais recente em github.com/cli/cli/releases, confira o checksum e copie bin/gh para ~/.local/bin/.

"fatal: '/tmp/pn-ghp' already exists" ao criar a worktree

Sobrou uma pasta temporária de uma atualização anterior. Remova e tente de novo:

git worktree remove --force /tmp/pn-ghp
git worktree prune
O push foi rejeitado ("rejected", "non-fast-forward")

O gh-pages remoto tem commits que a sua cópia não tem (ex.: alguém publicou de outro computador). Integre e reenvie:

git -C /tmp/pn-ghp pull --rebase
git -C /tmp/pn-ghp push
O site não mudou depois do push
  • Aguarde 1–2 minutos e confira o status do build com gh api repos/pedromfnakashima/pn-0001/pages/builds/latest --jq .status.
  • Recarregue sem cache (Ctrl+Shift+R). O CDN do GitHub pode manter a versão antiga por até ~10 minutos.
  • Confirme que o arquivo enviado é o novo: git log -1 --stat origin/gh-pages.
Status do build "errored"

Na primeira publicação o status passou por "errored" e depois ficou "built" sozinho, o que é normal na ativação. Se persistir:

gh api repos/pedromfnakashima/pn-0001/pages/builds/latest --jq '.error.message'
gh api -X POST repos/pedromfnakashima/pn-0001/pages/builds   # força um novo build

Confira também se o .nojekyll continua no branch gh-pages.
